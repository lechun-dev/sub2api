# 分组客户端访问策略

## 已确认的范围
- 客户端集中维护；内置 Codex 官方客户端和 DeepSeek Harness，可添加简单请求头识别规则。
- 分组按唯一 ID 配置 `off`、`allow`、`deny`，客户端多选；限制模式不能为空。
- 默认不限制。白名单未识别则拒绝，黑名单未识别则允许；多条客户端规则命中时，黑名单任一命中即拒绝。
- Key 鉴权之后、合成路由/账号调度之前检查，覆盖原生、兼容、根路径及 WebSocket 握手，不改变账号级限制。
- 返回动态中文提示和稳定错误码；维护 API 仅管理员可访问，沿用审计和合规守卫。

## 实现与边界
- 复用 settings 保存单个配置文档，包含客户端和 group ID 策略映射；不新增 SQL 表。
- 基于原始配置 CAS 保存，冲突返回 409；被引用的规则不可删除或停用。
- 热路径使用最多 2 秒的进程缓存；保存清除本实例缓存，其他实例最长 2 秒观察到变更。
- 配置损坏/数据库读取失败返回 503，不使用无限期陈旧配置放行。
- 分组复制同步复制策略，删除同步清理策略，均与分组变更同事务提交。
- Responses WebSocket 每轮复核最新策略，拒绝时发送动态错误帧并关闭连接；其他实时协议仅检查握手，不主动打断已开始的流。
- 客户端标识可伪造，不属于密码学身份认证；自定义头不得配置凭据或 Cookie。
- Harness 默认 User-Agent `deepseek-harness/<version> (+<url>)` 已由本地官方源码确认；白标分支需另建规则。
- 客户端/策略维护在“分组管理 → 客户端访问管理”，先建立分组，再按 ID 配置。
- 实现阶段不自动发布或部署；采用现有 Go/Gin/Ent、Vue/TypeScript 风格，不新增依赖。

## 使用入口
1. 全局入口：管理后台“分组管理”右上角点击“客户端访问管理”，默认展示已经配置限制的分组策略列表；未配置分组不受限制。
2. 新增策略：点击“新增分组策略”，只可选择尚未配置限制的分组，选择仅允许/禁止及客户端多选，核对提示预览后“保存策略”。每个分组仅一份策略，已有策略直接编辑。
3. 编辑/移除：列表提供“编辑”和“移除限制”。移除前确认，只恢复该分组不限制，不删除分组。所有分组均有策略时禁用新增并提示编辑已有策略。
4. 分组入口：分组行或编辑窗口进入带 group ID 的页面，直接显示该组名称和 ID，不显示分组搜索/选择或全局客户端编辑，按钮为“保存当前分组配置”。分组 ID 不存在、格式错误或不可访问时明确报错，不自动切换到另一组或全局模式。
5. 客户端管理：全局页面单独页签提供新增/维护识别规则，“保存客户端规则”仅修改客户端定义；分组页面“管理客户端”可跳转到此页签。被策略引用的客户端不可删除/停用。
6. 保存范围：仍复用原文档级 CAS 接口，只将当前组策略或客户端定义替换到已保存快照，其他配置保持不变。409 保留草稿；保存成功但 revision 回读失败时锁定后续写入，要求重新加载确认结果。
7. 页面离开、同一路由切换分组/入口及客户端页签切换会确认未保存草稿。Codex/DeepSeek 分组仍须独立绑定正确上游资源；新分组先保存基本信息，再配置访问策略。

## 数据核验（本项目为 PostgreSQL）
不涉及 MySQL DDL 或迁移。可只读检查 settings 中 `group_client_access_v1` 的存在及配置格式；不读取/输出 API Key、令牌或用户请求内容。

客户端识别只使用公开请求头，不读取提示词，不写模型用量。SQL 复用 Ent 参数化更新及既有分组锁函数；复制/删除会锁配置行，防止生命周期操作覆盖管理员保存。

## 策略日期与拦截日志（2026-10-14）
- 全局每条策略、当前分组配置页面显示创建/更新日期。日期由服务端维护，管理员提交的日期不会覆盖历史。新增或移除后重新启用的策略使用当前创建日期；修改模式、选择客户端或被引用的客户端定义会更新修改日期。不相关的客户端修改及重复保存不更新日期。
- 旧策略没有历史日期时显示“历史未记录”；首次修改只记录更新日期，不补造创建时间。复制分组时复制的策略记录新的创建/更新日期。
- 每条策略提供“拦截日志”；当前分组也可直接打开。按固定分组 ID 查询最近 24 小时 / 7 天 / 30 天，显示实际起止时间和浏览器时区，20 条分页。分页期间固定日期范围，刷新重新取截止时间。
- 显示拒绝时间、识别出的客户端、当时的允许/禁止客户端快照、原因、策略更新日期，以及用户名、数字 API Key ID、IP、Request ID、固定路由模板。规则和名称后续改变，不重判历史日志。
- 未识别、识别到但不在允许列表、命中禁止列表均记录；允许请求、配置不可用 503、其他鉴权拒绝不计入此列表。Responses WebSocket 每轮复核被拒绝也记录，仍归属握手时原始分组；关闭连接后异步写入，日期为拒绝发生时间。
- 不记录明文 API Key、Cookie、Authorization、请求/响应正文、URL 参数或路由中的用户输入。User-Agent 仅按下方排查补充规则脱敏、限长后记录。只在快照中保存公开客户端 ID/名称，最多各 8 个、名称最多 48 字，显示完整命中数量。
- 复用既有 `ops_error_logs` 表、异步队列、分组/日期索引及清理任务，无数据库迁移。只有开启运维监控才收集/查询；禁用时明确提示，不假装查询结果为空。记录归类为客户端业务限制，不计作上游可用性失败。
- 此处是最佳努力的运维记录，不是保证不丢失的审计流水；队列过载可能丢弃，写入可能延迟，记录会按既有 Ops 保留期限清理。旧入口拒绝聚合无法补出历史客户端/分组快照，详细记录从部署此功能后开始。
- 管理 API：`GET /api/v1/admin/ops/client-policy-denials`，必传 `group_id`；支持 `start_time`/`end_time`（ISO 时间）或 `time_range`，窗口最多 30 天，分页最多 100 条，保留既有管理员鉴权。
